## Why

当前项目已经具备后端诊断、证据管理、报告生成和恢复建议能力，但前端仍缺少面向用户的完整入口。需要新增一个对话式前端体验，让用户可以通过连续交互完成问题描述、证据补充、诊断触发、报告确认和恢复建议查看，形成可演示、可测试的诊断闭环。

## What Changes

- 新增 React 对话式诊断入口，用户可以像排障助手一样逐步提交故障描述、日志、jstack 和指标证据。
- 前端与现有后端 API 配合，串联创建故障会话、上传证据、触发诊断、读取报告、生成恢复建议和展示复盘信息。
- 新增前端会话状态管理，清晰表达收集证据、诊断中、等待确认、建议生成和完成等阶段。
- 新增前端并发保护：诊断触发、防重复提交、接口请求限流、配置开关和可观测的任务命名约定。
- 新增前端业务单元测试，覆盖对话流程、API 编排、异常提示、并发防护和配置开关。
- 前端业务代码使用英文命名和文案结构；必要注释尽量使用中文解释业务意图、并发边界和配置约束。

## Capabilities

### New Capabilities

- `conversational-diagnosis-frontend`: 提供面向用户的 React 对话式诊断入口，编排后端诊断 API，完成问题诊断闭环，并约束前端并发、限流、配置开关和测试覆盖。

### Modified Capabilities

- 无。

## Impact

- 影响 `frontend/` React 应用结构、组件、状态管理、API 客户端和测试配置。
- 可能新增或调整前端依赖，例如测试工具、请求封装、限流工具或轻量状态管理工具。
- 后端 API 原则上不新增破坏性变更；如发现缺少闭环所需字段，应通过兼容方式扩展响应。
- 需要保证 `mvn test` 继续通过，并新增前端测试命令用于验证 React 业务代码。
## Addendum: Internationalization and Tips

新增要求：

- 所有界面展示文案必须通过前端国际化资源管理，默认语言为中文。
- 对话消息、阶段状态、按钮、表单标签、错误提示、空状态和报告区域展示文案都不得散落硬编码在组件中。
- 关键按钮和输入框必须提供明确 tip，用于说明操作影响、输入格式、是否会调用后端以及失败后的处理方式。
- 国际化和 tip 逻辑需要补充前端业务测试，覆盖默认中文展示、语言资源读取和关键控件 tip 存在性。

影响：

- 影响 React 前端展示层、对话消息派生、表单控件、按钮、错误提示和测试用例。
- 不要求新增后端国际化能力；本次范围限定为前端展示文案和控件提示。
